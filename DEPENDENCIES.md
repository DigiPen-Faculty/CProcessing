# Third-party dependencies

This file records every third-party library CProcessing uses, exactly which
version is in use, how it gets into the build, and how to update it.

## Policy

Every dependency is **pinned to an exact version and recorded here**, so it is
always possible to tell which upstream fixes (or security advisories) apply.

There are three ways a dependency gets into the build:

| How | Used for | Why |
|---|---|---|
| **Source in the repo** | NanoVG, GLAD, tinycthread, Unity | Small, plain C, rarely updated, and in NanoVG's case carrying local changes. Works for every build, including a GitHub "Download ZIP". |
| **Prebuilt Windows binaries in the repo** | GLFW, SoLoud (Visual Studio solution only) | The Visual Studio workflow students and faculty use needs no extra tools or downloads. |
| **Downloaded by CMake at configure time** | GLFW, SoLoud, miniaudio (CMake build only) | Built from source for whichever platform is being targeted. Each download is pinned to a URL *and* verified against a SHA-256 hash in [cmake/CProcessingDependencies.cmake](cmake/CProcessingDependencies.cmake). |

Git submodules were considered and deliberately not used. GitHub's
"Download ZIP" does not include submodule contents, and a plain `git clone`
without `--recursive` leaves them empty. Both are easy mistakes for students
to make, and they produce confusing build errors. CMake's pinned and hashed
downloads give the same exact-version guarantee without either problem.

### Why the two builds use different GLFW and SoLoud versions

The prebuilt Windows binaries were left exactly as they were, so the Visual
Studio build students use does not change. The CMake build needs newer
versions to work correctly on Linux:

- **GLFW 3.5.1:** GLFW 3.4's Wayland backend crashes at startup when the
  compositor has not yet advertised an input seat, which happens
  intermittently. 3.5.1 handles it.
- **SoLoud master:** this carries four years of fixes made after the 2020
  release, including voice-group allocation, which CProcessing uses. Its C API
  is a superset of the 2020 one.
- **miniaudio 0.11.25:** SoLoud bundles miniaudio 0.10.42. Its PulseAudio
  code dereferences a NULL pointer during device setup, which crashed
  CProcessing intermittently on Linux desktops.

Bringing the prebuilt Windows binaries up to the same versions is a
reasonable follow-up. The CMake build can produce those binaries directly.

### NanoVG local changes

NanoVG is effectively a small fork. Changes made in this repository on top of
upstream include:

- `nvgGetImagePixelsRGBA()`, which reads an image's pixels back and backs
  `CP_Image_GetPixelData`.
- Font freeing support in NanoVG and fontstash, backing `CP_Font_Free`.
- Point drawing that uses the stroke color, width and cap, backing
  `CP_Graphics_DrawPoint`.
- Shutdown leak fixes, and save/restore surviving screenshots.

See `git log -- Processing_Sample/CProcessing/nanovg` for the full history.
Updating NanoVG from upstream means re-applying these changes.

## How to update a dependency

### GLFW, SoLoud or miniaudio (CMake build)

1. Pick the new release, or for SoLoud a commit, and download its archive.
2. Compute its hash, for example with `sha256sum file.zip` or PowerShell's
   `Get-FileHash file.zip`.
3. Update the version, URL and SHA-256 in
   [cmake/CProcessingDependencies.cmake](cmake/CProcessingDependencies.cmake),
   and the inventory table above.
4. Delete the build folder, or at least its `_deps` folder, then reconfigure,
   build and run `ctest`. CI runs the same checks on Windows, Linux and macOS.

### GLFW or SoLoud prebuilt Windows binaries (Visual Studio build)

1. Build static `glfw3.lib` and the `soloud`/`soloud_d` DLLs for x64 and x86,
   in Debug and Release, with the same Visual Studio toolset as
   `CProcessing.vcxproj`.
2. Replace the files under `Processing_Sample/CProcessing/GLFW/` or
   `Processing_Sample/CProcessing/soloud/`, and the matching headers.
3. Update `Version.txt` or `readme.txt` in that folder and the inventory table
   above.
4. Build the solution in all four configurations and run both test projects.

### In-repo sources (NanoVG, GLAD, TinyCThread, Unity)

Copy the new upstream files over the old ones in a commit of their own, with
the upstream commit or version in the commit message. Re-apply any local
changes (see NanoVG above), update the table, then build and run the tests
with both build systems.

### Offline builds

CMake can use local copies instead of downloading:

```
cmake -B build -DFETCHCONTENT_SOURCE_DIR_GLFW=/path/to/glfw-3.5.1 \
               -DFETCHCONTENT_SOURCE_DIR_SOLOUD=/path/to/soloud \
               -DFETCHCONTENT_SOURCE_DIR_MINIAUDIO=/path/to/miniaudio
```
