# Third-party dependencies

This file records every third-party library CProcessing uses, exactly which
version is in use, how it gets into the build, and how to update it.

## Policy

Every dependency is **pinned to an exact version and recorded here**, so it is
always possible to tell which upstream fixes (or security advisories) apply.

There are three ways a dependency gets into the build:

| How | Used for | Why |
|---|---|---|
| **Source in the repo** | NanoVG, GLAD, tinycthread, Unity | Small, plain C, rarely updated, and in NanoVG's case carrying local changes. Works for every build, including a GitHub "Download ZIP". |
| **Downloaded by CMake at configure time** | GLFW, SoLoud, miniaudio | Built from source for whichever platform is being targeted. Each download is pinned to a URL *and* verified against a SHA-256 hash in [cmake/CProcessingDependencies.cmake](cmake/CProcessingDependencies.cmake). |
| **Prebuilt static libraries in the repo** | GLFW, SoLoud + miniaudio (for the Visual Studio solution) | Produced from those **same pins** by [tools/update-windows-prebuilt.ps1](tools/update-windows-prebuilt.ps1), so the Visual Studio workflow needs no extra tools or downloads while using exactly the same versions as every other build. |

`cmake/CProcessingDependencies.cmake` is the single place GLFW, SoLoud and
miniaudio versions are set, for every platform and both build systems.

Third-party source in the repository is compiled as-is, with its warnings
turned off in both build systems. Local edits to it are made only to change
behavior, never to silence a warning, and each one is recorded.

Git submodules were considered and deliberately not used. GitHub's
"Download ZIP" does not include submodule contents, and a plain `git clone`
without `--recursive` leaves them empty. Both are easy mistakes for students
to make, and they produce confusing build errors. CMake's pinned and hashed
downloads give the same exact-version guarantee without either problem.

### Why these versions

- **GLFW 3.5.1** rather than 3.4: GLFW 3.4's Wayland backend crashes at
  startup when the compositor has not yet advertised an input seat, which
  happens intermittently. 3.5.1 handles it.
- **SoLoud master** rather than the last tagged release (RELEASE_20200207):
  master carries four years of fixes, including voice-group allocation, which
  CProcessing uses. Its C API is a superset of the 2020 one.
- **miniaudio 0.11.25** instead of the 0.10.42 SoLoud bundles: 0.10.42's
  PulseAudio code dereferences a NULL pointer during device setup, which
  crashed CProcessing intermittently on Linux desktops.
- **NanoVG ce3bf74**, its latest commit: NanoVG has no releases or tags,
  and is no longer actively maintained. Until CProcessing 3.0 the copy here
  dated from April 2018 (`30a943c`) and was missing several fixes that
  CProcessing needs, such as text vanishing under a mirroring transform.

SoLoud and miniaudio are linked **statically** into the CProcessing library
on every platform, so there is no separate `soloud.dll` to ship. With no audio
device, SoLoud falls back to its silent "nosound" backend.

### NanoVG patches

CProcessing carries a small set of patches to NanoVG: tint, image filter
and wrap modes set per draw, blend modes that need a blend equation,
settings that last from one frame to the next, and freeing fonts.
[nanovg/CPROCESSING.md](Processing_Sample/CProcessing/nanovg/CPROCESSING.md)
lists each one, what uses it and why it has to be inside NanoVG. Every
patched line is marked with a `// CProcessing:` comment, and
[tools/nanovg-diff.sh](tools/nanovg-diff.sh) prints the exact difference
from the upstream commit.

## How to update a dependency

### GLFW, SoLoud or miniaudio

1. Pick the new release, or for SoLoud a commit, and download its archive.
2. Compute its hash, for example with `sha256sum file.zip` or PowerShell's
   `Get-FileHash file.zip`.
3. Update the version, URL and SHA-256 in
   [cmake/CProcessingDependencies.cmake](cmake/CProcessingDependencies.cmake),
   and the inventory table above.
4. Delete the build folder, or at least its `_deps` folder, then reconfigure,
   build and run `ctest`.
5. On Windows, run
   `powershell -ExecutionPolicy Bypass -File tools\update-windows-prebuilt.ps1`.
   It rebuilds the prebuilt libraries and headers the Visual Studio solution
   uses (x64 and x86, Debug and Release) from the new pins. It also rewrites
   their `Version.txt` files.
6. Build `Processing_Sample.sln` in all four configurations and run both test
   projects. Commit the pin change and the regenerated binaries together. CI
   checks both build systems on Windows, Linux and macOS.

### In-repo sources (NanoVG, GLAD, TinyCThread, Unity)

Copy the new upstream files over the old ones in a commit of their own, with
the upstream commit or version in the commit message. Update the table, then
build and run the tests with both build systems.

For NanoVG, follow "Updating to a newer upstream commit" in
[nanovg/CPROCESSING.md](Processing_Sample/CProcessing/nanovg/CPROCESSING.md),
which merges CProcessing's patches into the new version.

### Offline builds

CMake can use local copies instead of downloading:

```
cmake -B build -DFETCHCONTENT_SOURCE_DIR_GLFW=/path/to/glfw-3.5.1 \
               -DFETCHCONTENT_SOURCE_DIR_SOLOUD=/path/to/soloud \
               -DFETCHCONTENT_SOURCE_DIR_MINIAUDIO=/path/to/miniaudio
```
